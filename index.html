為什麼需要這個

現有隱私防護工具對台灣個資幾乎無法偵測 —— 這是我們實測出來的數字，不是推論。

偵測類別PresidioGLiNERLLM Guard本作品
人名0.4470.1001.000語意層 0.976
地址0.0000.2021.000語意層支援
身分證字號0.0000.1760.000檢核碼驗證
統一編號0.0000.0000.000檢核碼驗證

數值為 recall（召回率）。測試語料為 300 筆合成台灣個資，涵蓋醫療對話、履歷、客服記錄三種情境， 全數為假資料；每個身分證與統編各生成「檢核碼正確」與「錯誤」兩版。固定 random seed、鎖定套件版本。
關鍵解讀：LLM Guard 在人名與地址上達到滿分 1.000，同一次執行卻在身分證上掛零 —— 不是中文能力不足，是設計裡從來沒有台灣。而且沒有任何一個現有工具驗證檢核碼。

輸入：一段「每個欄位單獨看都不算個資」的文字

這位患者 32 歲男性，住在新竹市東區，是某科技公司的資深後端工程師，上週因罕見疾病在本院門診追蹤。
組合風險 1.00（高）：ADDRESS、AGE、COMPANY、GENDER、POSITION 同時出現， 即使明碼個資已遮蔽，仍可能指認到特定個人 · 地址建議泛化到市/縣級（例如「信義區光復路259巷」→「台北市」） · 「32歲」建議泛化為「30-34歲」 · 公司名稱可模糊化為產業別（例如「某科技公司」） · 若非必要，建議省略性別資訊 · 職稱可保留，但建議避免同時透露服務公司名稱

這裡面沒有任何一個欄位是傳統定義的「個資」 —— 沒有姓名、沒有身分證、沒有電話。但年齡 + 居住地 + 公司 + 職稱 + 性別湊在一起， 就足以指認到特定個人。

我們的策略是「提示」而不是「強行遮蔽」：全部遮掉會讓 AI 無法作答 （「32 歲」被遮掉，醫療諮詢就失去意義），所以系統估算風險、給出泛化建議， 由使用者自己決定。arXiv 2026 的論文實測八種去識別化技術後， 「隱含身分」的語意洩漏率仍高達 95% —— 這是公認的開放問題， 而現有工具全數沒有這個功能。

系統怎麼運作

語言模型判斷「像不像」，檢核碼判斷「是不是」—— 個資防護兩者都需要。

L1 規則驗證層身分證、統編、健保卡號的檢核碼演算法，確定性判定
L2 語意偵測層本地 NER 小模型處理人名、地址、機構等上下文實體
L3 組合風險評分偵測準識別子共現，估算再識別風險並提出警示
還原AI 回覆時依固定格式把佔位符換回真值，使用者無感

兩個載體，一個核心

瀏覽器擴充（面向一般使用者）

選取文字按右鍵「隱私處理後貼上」，貼進 ChatGPT 的已經是遮蔽後的內容。 側邊面板即時顯示偵測到什麼、風險多少。TypeScript 實作。

API Proxy（面向開發者）

攔在 AI coding agent 與雲端 LLM 之間。Agent 讀到 .env 或客戶名單時自動攔下， 回覆時自動還原，工作流程完全不變。Python 實作。

誰該用哪一個

兩個載體面向的使用者不同。先看你是哪一種。

一般民眾 要把租賃契約、履歷、病歷貼給 ChatGPT 問問題，但不想連身分證跟住址一起送出去。
→ 用瀏覽器擴充。選取文字按右鍵「隱私處理後貼上」即可，不用裝 Python。
開發者 用 Aider / Cline / Codex 這類 AI coding agent，但專案裡有 .env、 有客戶名單，agent 自己讀檔你根本不知道它送了什麼出去。
→ 用 API Proxy。改一行 base URL，工作流程完全不變。
醫療 / 法律 / 會計 受職業保密義務規範，現在幾乎不敢碰 AI 工具。
→ 兩個都用，並開啟語意層。人名、地址、病歷號都要擋，組合風險提示也用得上。
中小企業 沒預算導入企業級 DLP 方案，但一樣有個資法與 AI 基本法的法遵義務。
→ 團隊共用一台 Proxy。集中稽核，但資料仍然不出內網。

語意層預設關閉是刻意的：它會讓每個請求多付一筆推論成本，而且 torch / transformers 體積很大。只有在需要遮蔽人名、地址時才開 （PII_ENABLE_NER=1）。關閉時 proxy 完全不會 import 這些套件， 不裝也跑得起來。

套件版本全部鎖死，不擅自升級 —— 團隊踩過「降級改變實驗結果」的坑。

導入長什麼樣子

以 Aider 為例，一行環境變數

# 1. 啟動本地 proxy .venv\Scripts\python.exe -m uvicorn proxy.main:app --port 8010 # 2. 讓 agent 指向它 set OPENAI_API_BASE=http://127.0.0.1:8010/v1 # 3. 照常使用 —— 工作流程完全不變 aider

其他 agent 只差在「怎麼告訴它 base URL 換了」：Cline 在 GUI 填、 Continue 改 config.yaml、Codex 與 OpenCode 改自己的設定檔、 Claude Code 設 ANTHROPIC_BASE_URL。 遮蔽與還原的邏輯完全共用，不是六套程式。

我們知道自己的限制

  • 關聯性洩漏（刻意取捨）：「[NAME_1] 的電話是 [TW_PHONE_M_1]」這個關聯本身仍然保留。 要讓 AI 還能正常做事，就不能把結構也打碎。
  • 組合風險只提示、不強制遮蔽：由使用者判斷。過度遮蔽會讓 AI 無法作答。
  • 計數是「不重複字面值」不是「不重複當事人」：同一張身分證的全形與半形寫法會拿到兩個佔位符， 因為還原時必須知道原本是哪種寫法 —— 統一正規化等於偷改使用者原文。
  • 這個展示頁只跑規則層（L1）：語意層需要下載 NER 模型，不適合放在網頁裡。 人名、地址的偵測請用完整版。
